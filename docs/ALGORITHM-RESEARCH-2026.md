# Исследование алгоритмов очистки — август 2026

## Что подтвердили первичные источники

- Apple: локальные снимки Time Machine на APFS могут продолжать хранить прежнее
  содержимое уже изменённых или удалённых файлов; macOS считает это место доступным и
  освобождает его по требованию. Это не обычная скрытая папка, которую корректно
  показывать как безопасную цель удаления.
  [Apple Support](https://support.apple.com/en-us/102154)
- Apple: `fileContentIdentifierKey` одинаков только у APFS-клона и его оригинала.
  Это публичный системный признак для отличия настоящей второй копии от общих блоков.
  [Apple Developer](https://developer.apple.com/documentation/foundation/urlresourcekey/filecontentidentifierkey)
- DaisyDisk считает classic hard links один раз и на macOS 14+ так же объединяет полные
  APFS-клоны. Частично общие блоки APFS публичными API точно посчитать нельзя.
  [DaisyDisk](https://web.daisydiskapp.com/guide/hard-links)
- DaisyDisk разделяет сканируемые файлы, purgeable space, другие APFS-тома и всё ещё
  скрытое место; их нельзя складывать в одну цифру «мусор».
  [DaisyDisk](https://daisydiskapp.com/guide/4/en/HiddenSpace/)
- CleanMyMac строит автоматический выбор поверх обновляемой Safety Database и по
  умолчанию выбирает только автоматически созданные данные, сохраняя отдельные
  исключения для дорогих кэшей и пользовательских данных.
  [CleanMyMac Safety](https://macpaw.com/support/cleanmymac/knowledgebase/cleanmymac-safety)
- Nektony подтверждает полезную схему для дубликатов: сравнение содержимого, несколько
  выбранных корней, отдельный просмотр скрытых папок и package contents, плюс правила
  авто-выбора вместо безусловного удаления.
  [Duplicate File Finder](https://nektony.com/help/duplicate-file-finder/faq)
- Apple рекомендует для повторных больших обходов хранить снимок и использовать
  FSEvents для инвалидации изменившихся каталогов, включая изменения во время скана.
  Нельзя разбирать внутренние файлы `.fseventsd`: их формат не является API.
  [FSEvents Programming Guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html)
- Apple Vision создаёт feature print изображения и сравнивает два отпечатка расстоянием:
  меньшее расстояние означает большее сходство. В WWDC26 Apple отдельно рекомендует
  вычислять отпечатки заранее, хранить их локально, применять верхний порог и ограничивать
  число результатов.
  [Vision](https://developer.apple.com/documentation/vision/analyzing-image-similarity-with-feature-print),
  [WWDC26](https://developer.apple.com/videos/play/wwdc2026/297/)
- CleanMyMac (обновление от 6 августа 2026) группирует похожие изображения, показывает
  превью/метаданные и предлагает сохраняемый кадр, но удаление остаётся проверяемым
  пользователем. Gemini 2 прямо отделяет точные дубли, которые можно выбрать автоматически,
  от похожих файлов, требующих ручного просмотра.
  [CleanMyMac Similar Images](https://cms-static.macpaw.com/support/cleanmymac/knowledgebase/similar-images),
  [Gemini Smart Cleanup](https://macpaw.com/support/gemini/knowledgebase/gemini-2-smart-selection)
- Duplicate File Finder 9.1 добавил регулируемую степень сходства; его документация также
  подтверждает скан нескольких дисков, скрытых папок и package contents, а для похожих фото —
  отдельное сравнение и выбор сохраняемой версии.
  [Release notes](https://nektony.com/duplicate-finder-free/download),
  [FAQ](https://nektony.com/help/duplicate-file-finder/faq)
- Duplicate File Finder отдельно определяет duplicate folder как дерево, где совпадает
  каждый файл и подкаталог, а similar folder — как частично совпадающее дерево. Для точного
  дубля целая папка является более понятной и быстрой единицей удаления, чем десятки её
  файлов; обычный способ удаления у конкурента — перенос в Корзину.
  [Getting started](https://nektony.com/help/duplicate-file-finder/getting-started),
  [FAQ](https://nektony.com/help/duplicate-file-finder/faq)
- Gemini Duplicates Monitor наблюдает за уже очищенными папками и сообщает о новых копиях.
  Это подтверждает пользу инкрементального индекса, но не отменяет требование Apple заново
  сканировать каталог после dropped FSEvents.
  [Gemini Monitor](https://macpaw.com/support/gemini/knowledgebase/about-duplicates-monitor),
  [FSEvents](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html)
- В актуальной документации Gemini домашний каталог прямо обозначен как долгий скан,
  Duplicates Monitor следит только за выбранными/очищенными местами, а правила выбора можно
  сохранять по папкам. CleanMyMac группирует точные дубли, хранит ignore list и отделяет их
  от Similar Images; это подтверждает необходимость возобновляемой очереди и явных границ,
  а не одного бесконечного полного обхода.
  [Gemini scanning](https://macpaw.com/support/gemini/knowledgebase/start-scanning-for-duplicates),
  [Gemini preferences](https://macpaw.com/support/gemini/knowledgebase/gemini-2-preferences-settings),
  [CleanMyMac duplicates](https://macpaw.com/support/cleanmymac/knowledgebase/duplicate-files)

## Что внедрено

1. Трёхступенчатый поиск дубликатов: логический размер → три 64 KiB-сэмпла
   (начало/середина/конец) → полный SHA-256. До и после чтения проверяются inode,
   размер, `mtime` и `ctime`, поэтому меняющийся во время скана файл не станет дублем.
2. Classic hard links определяются по `device + inode + link count`. Второе имя получает
   нулевую оценку освобождения и read-only объяснение.
3. Полные APFS-клоны определяются через `fileContentIdentifier` и
   `mayShareFileContent`. Они не раздувают обещание очистки; частичные клоны считаются
   консервативно, поскольку точного публичного счётчика общих блоков нет.
4. Большие файлы показывают физически выделенный объём. Sparse-файлы, hard links и
   APFS-клоны больше не выдаются за полностью освобождаемый логический размер.
5. iCloud/File Provider dataless placeholders пропускаются до открытия файла, чтобы
   скан сам не скачивал «мусор» из облака.
6. Глубокий скрытый индекс и бинарный поиск медиа не считают повторно hard links и
   полные APFS-клоны.
7. Добавлена отдельная read-only карточка системно удерживаемого места: свободно прямо
   сейчас, оценка доступного macOS резерва, APFS-снимки и защищённые версии документов.
8. Все audit-карточки исключены из общей цифры «можно очистить», даже если показывают
   большой реально занятый системный store.
9. В bundle добавлен privacy manifest для disk-space, file-timestamp и UserDefaults API;
   приложение декларирует отсутствие tracking и сбора данных.
10. Добавлен отдельный поиск копий скриншотов после переименования, масштабирования и
    JPEG/HEIC-сжатия: совпадение допускается только после одинаковой формы кадра, трёх
    независимых 64-битных pixel hashes и строгого Apple Vision feature print.
11. Похожее изображение никогда не входит в «Отметить безопасное». Доступный обычный файл
    можно выбрать только вручную, а совпадение внутри Library, temp, recovery, Cursor/Claude
    и другого скрытого store навсегда остаётся read-only карточкой.
12. Область точных дубликатов расширена с Desktop/Documents/Downloads на Pictures и Movies.
    Группы теперь сортируются от самых крупных, лимит поднят с 60 до 240 результатов.
13. SHA-256, трёхточечные sample hashes и pixel hashes имеют ограниченный персистентный
    индекс без путей и содержимого. Ключ включает device/inode/size/mtime/ctime; изменение
    файла делает старую запись недоступной. На текущем профиле второй реальный проход
    раздела дубликатов ускорился примерно с 83 до 50 секунд.
14. Spotlight-индекс скрытых captures/media повторно используется внутри одного полного
    прохода, но каждый путь заново проверяется через `lstat`/allocated bytes перед декодом.
15. Добавлены точные дубликаты целых папок. Дешёвый проход строит Merkle-подобную форму из
    относительных путей, пустых подкаталогов и размеров; полный SHA-256 каждого файла читается
    только у деревьев одинаковой формы. `.DS_Store` не влияет на равенство.
16. Whole-folder карточка всегда выключена по умолчанию. Symlink, package/mount, облачный
    placeholder, пользовательское исключение и защищённое вложение дисквалифицируют всё дерево.
    Hard links/APFS clones остаются audit-only и не раздувают обещание освобождения места.
17. Перед удалением обе папки полностью индексируются и хешируются заново. Любой новый,
    исчезнувший или изменившийся файл отменяет операцию; после доказанного whole-folder дубля
    отдельные строки его дочерних файлов скрываются, чтобы не считать место дважды.
18. Обход папок получил каскад стоимости: обычный проход читает только структуру, размеры и
    статус облачной загрузки; APFS allocation/clone metadata запрашиваются лишь для одинаковых
    форм. Большие корни получают справедливый лимит, а незаконченный top-level subtree целиком
    инвалидируется и никогда не превращается в результат. Частичное покрытие явно показывается
    отдельной read-only карточкой и не маскируется под «дубликатов нет».
19. Верхние папки превращены в независимую циклическую очередь. Курсор сохраняется только
    после готового результата; следующий запуск начинает с другой позиции. У каждой задачи
    есть собственный лимит, поэтому один `node_modules`/репозиторий не блокирует Pictures,
    Movies и остальные Downloads. Последняя четверть общего времени зарезервирована под
    полный SHA-256 и APFS-проверку shortlist, а не расходуется на бесконечное перечисление.
20. Скрытые папки в пользовательских корнях теперь участвуют в exact whole-folder поиске.
    При этом PostgreSQL, MongoDB, MySQL, Redis и Elasticsearch распознаются по компонентам
    пути и engine marker-файлам. Даже байтово одинаковые database pages никогда не становятся
    карточкой удаления; эта же граница повторяется непосредственно перед Janitor.
21. На текущем профиле первый новый проход вырос примерно с 26 тысяч объектов/440 builders
    до 59 тысяч/1 143, сохранил следующую позицию, а второй с другой точки проверил 52 тысячи
    объектов и провёл полный hash 7 160 файлов. Реальный найденный PostgreSQL false positive
    послужил регрессией и после добавления DB-boundary исчез из результатов.

## Следующие независимые итерации

- персистентный индекс с FSEvents-инвалидацией для быстрых повторных сканов;
- выбор произвольных локальных/внешних томов для дубликатов с отдельной физической
  бухгалтерией каждого APFS container;
- отдельный preview/Quick Look экран сравнения и регулируемый уровень сходства для
  пользовательских фото; строгий capture-режим останется отдельным;
- similar-folder группы и правила «всегда сохранять/выбирать в этой папке»; exact whole-folder
  сравнение уже внедрено, но остаётся только ручным;
- versioned ruleset владельцев приложений и их disposable/sensitive путей с
  регрессионными fixtures на каждое изменение.
